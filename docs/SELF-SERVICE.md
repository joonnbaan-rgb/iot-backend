# สมัครใช้งานเอง (Self-service) และการแชร์

## ภาพรวมบทบาท
| ใคร | ทำอะไรได้ |
|---|---|
| ผู้ใช้ที่สมัครเอง | เพิ่มอุปกรณ์ของตัวเอง → เป็น **เจ้าของ (ผู้ดูแล)** อุปกรณ์นั้น, สร้างไซต์/กลุ่ม, แชร์ให้บัญชีอื่น, เปลี่ยนรหัสผ่าน |
| ผู้รับแชร์ | `ดูอย่างเดียว` / `ควบคุมได้` / `ผู้จัดการร่วม` (แก้ไข-ตั้งค่า-ลบได้ แต่แชร์ต่อ/โอนไม่ได้) |
| admin ระบบ | เห็นและจัดการอุปกรณ์ของทุกคน, ปรับโควตา, ระงับบัญชี, สร้างอุปกรณ์แทนผู้ใช้, โอนอุปกรณ์ |

## ตั้งค่าเซิร์ฟเวอร์ (`.env` / `.env.prod`)
```
REGISTRATION_MODE=open        # open | invite | closed   (prod ค่าเริ่มต้นคือ invite)
DEFAULT_DEVICE_QUOTA=20       # โควตาอุปกรณ์ต่อผู้ใช้ (admin ไม่จำกัด)
DEFAULT_SITE_QUOTA=5          # โควตาไซต์ที่สร้างเพิ่ม (ไม่นับไซต์ส่วนตัว)
REQUIRE_EMAIL_VERIFICATION=false   # true = ต้องยืนยันอีเมลตอนสมัคร
RESEND_API_KEY=...            # ต้องมี (พร้อม EMAIL_FROM) ถ้าต้องการ "ลืมรหัสผ่าน" และอีเมลเชิญแชร์
```
เปิดให้สมัครเองบน production: แก้ `REGISTRATION_MODE=open` ใน `.env.prod` แล้ว `docker compose -f docker-compose.prod.yml up -d backend`
(การสมัครจำกัด 10 ครั้ง/10 นาที/IP)

### ยืนยันอีเมลตอนสมัคร
ตั้ง `REQUIRE_EMAIL_VERIFICATION=true` (ต้องตั้ง `RESEND_API_KEY` + `EMAIL_FROM` ด้วย — ถ้ายังไม่ตั้ง: production จะข้ามขั้นตอนนี้และเตือนในล็อก ไม่ล็อกผู้ใช้; โหมดพัฒนา (NODE_ENV ไม่ใช่ production) ยังบังคับยืนยันและพิมพ์รหัสลงล็อก `docker compose logs backend | Select-String "รหัสยืนยัน"`)
- สมัครแล้วระบบส่งรหัส 8 หลัก (30 นาที, ลองผิดได้ 5 ครั้ง, ขอใหม่ได้ทุก 1 นาที) ผู้ใช้ login ไม่ได้จนกว่าจะยืนยัน (`POST /auth/verify-email`, `POST /auth/resend-verification`)
- ผู้ใช้คนแรก (admin) และผู้ที่สมัครด้วยรหัสเชิญไม่ต้องยืนยันซ้ำ; ผู้ใช้เดิมถือว่ายืนยันแล้ว
- แชร์ที่ค้างอยู่ (คำเชิญ) จะมีผลหลังยืนยันอีเมลเท่านั้น กันคนสมัครด้วยอีเมลของผู้อื่นแล้วรับแชร์ไป
- ใช้ "ลืมรหัสผ่าน" สำเร็จ = ยืนยันอีเมลอัตโนมัติ

## ฟีเจอร์ใหม่ (API)
- `GET /auth/config` (สาธารณะ) โหมดสมัคร + มีระบบรีเซ็ตรหัสผ่านหรือไม่ — แอปใช้ซ่อน/แสดงช่องรหัสเชิญ
- `POST /auth/forgot-password` → ส่งรหัส 8 หลักทางอีเมล (30 นาที, ลองผิดได้ 5 ครั้ง) · `POST /auth/reset-password` · `POST /auth/change-password` (ออกจากระบบอุปกรณ์อื่นทั้งหมด)
- `GET /auth/usage` โควตาที่ใช้/ทั้งหมดของฉัน
- `POST /devices` ครบโควตา → 403 · admin ส่ง `owner_id` เพื่อสร้างแทนผู้ใช้
- `POST /devices/:id/transfer {email}` โอนความเป็นเจ้าของ (เจ้าของหรือ admin) — ล้างการแชร์/กลุ่มเดิมของอุปกรณ์นั้น
- `POST /shares` permission = `view|control|manage`; ถ้าอีเมลผู้รับ **ยังไม่สมัคร** จะเก็บเป็นคำเชิญ (`GET /shares/pending`, `DELETE /shares/pending/:id`, สูงสุด 50) แล้วมีผลอัตโนมัติเมื่อสมัครด้วยอีเมลนั้น
- admin: `GET /users` (พร้อมจำนวนอุปกรณ์/ไซต์/โควตา/เข้าใช้ล่าสุด), `PATCH /users/:id {device_quota, site_quota, status}`, `GET /users/:id/devices`

- admin ลบผู้ใช้: `DELETE /users/:id?devices=delete|transfer` (Web Admin: จัดการ → โซนอันตราย พิมพ์อีเมลยืนยัน)
- โอนอุปกรณ์: แอปมือถือ (แก้ไขอุปกรณ์ → โอนความเป็นเจ้าของ) และ Web Admin (หน้าอุปกรณ์ → ตั้งค่า) — ถ้าผู้ใช้มีอุปกรณ์ต้องเลือก `delete` (ลบพร้อมข้อมูลและสตรีม) หรือ `transfer` (โอนให้ admin ผู้สั่งลบ); ไซต์ที่เขาสร้างและยังมีคนอื่น/อุปกรณ์จะโอนให้ admin; rule ของเขาถูกลบ; ลบตัวเองไม่ได้

## ข้อจำกัดที่ควรรู้
- ลบผู้ใช้: access token ที่ออกไปแล้วยังใช้ได้จนหมดอายุ (≤15 นาที) แม้ข้อมูลหายแล้ว
- ระงับบัญชี: ตัด refresh token ทันที แต่ access token ที่ออกไปแล้วยังใช้ได้จนหมดอายุ (`JWT_EXPIRES_IN`, ค่าเริ่มต้น 15 นาที) และ socket ที่เชื่อมอยู่จะหลุดเมื่อเชื่อมต่อใหม่
- ผู้จัดการร่วม (`manage`) ลบอุปกรณ์/ออกรหัส MQTT ได้ ให้สิทธิ์นี้เฉพาะคนที่ไว้ใจ
- ถ้าตั้ง `REGISTRATION_MODE=invite` ผู้รับแชร์ที่ยังไม่สมัครต้องมีรหัสเชิญด้วย
- ยังไม่มีระบบชำระเงินออนไลน์: admin เป็นคนกำหนดแพ็กเกจและวันหมดอายุให้ผู้ใช้เอง (ดูหัวข้อ "ระบบสมาชิก")

## ระบบสมาชิก (แพ็กเกจ + วันหมดอายุ)
แพ็กเกจเริ่มต้น (แก้ได้ที่ Web Admin → ผู้ใช้และใบเชิญ → แพ็กเกจสมาชิก):

| แพ็กเกจ | อุปกรณ์ | ไซต์ | กล้อง | บันทึกคลิป | แจ้งเตือน | เก็บข้อมูลเซนเซอร์ |
|---|---|---|---|---|---|---|
| Free | 5 | 1 | 1 | ไม่ได้ | Telegram | 7 วัน |
| Pro | 20 | 5 | 4 | ได้ | Telegram, LINE, อีเมล | 90 วัน |
| Business | 200 | 50 | 32 | ได้ | ทุกช่องทาง | 365 วัน |

- ผู้สมัครใหม่ได้ Free; ผู้ใช้เดิมก่อนมีระบบนี้ถูกตั้งเป็น Pro (migration `Plans1700001500000`); admin ไม่จำกัดทุกอย่าง
- admin กำหนดแพ็กเกจ + วันหมดอายุรายคนที่ Web Admin → จัดการผู้ใช้ (ปุ่ม +30 วัน / +1 ปี / ไม่หมดอายุ) หรือ `PATCH /users/:id {plan_id, plan_expires_at}`; แก้สิทธิ์แพ็กเกจที่ `PATCH /plans/:id`; ผู้ใช้ดูแพ็กเกจของตัวเองที่ `GET /auth/usage` (แอป: แท็บบัญชี)
- หมดอายุแล้ว = ใช้สิทธิ์ของ Free ทันที: เพิ่มอุปกรณ์/ไซต์/กล้องเกินโควตาไม่ได้ (ของเดิมไม่ถูกลบ), คลิปที่อัดใหม่จะถูกทิ้ง, ช่องทางแจ้งเตือนที่ Free ไม่รองรับจะหยุดส่ง (ข้อมูลช่องทางยังอยู่ กลับมาใช้ได้เมื่อต่ออายุ)
- โควตาอุปกรณ์/ไซต์รายคนที่ admin ตั้งไว้ (ช่อง "โควตา") ยังใช้ override แพ็กเกจได้; `DEFAULT_DEVICE_QUOTA` / `DEFAULT_SITE_QUOTA` ใน env เลิกใช้แล้ว
- ข้อมูลเซนเซอร์ดิบที่เก่ากว่าอายุเก็บของแพ็กเกจจะถูกลบทุกวัน 03:30 (หลังหมดอายุเกิน 30 วันจึงนับเป็น Free) ข้อมูลสรุปรายชั่วโมงไม่ถูกลบ
- ยังไม่มีการชำระเงิน/ใบแจ้งหนี้ออนไลน์ และยังไม่ส่งอีเมลเตือนก่อนหมดอายุ

### แพ็กเกจที่ตั้งค่าเองได้ + สิทธิ์รายคน
- Web Admin → ผู้ใช้และใบเชิญ → "แพ็กเกจสมาชิก": แก้ได้ทุกค่า, **เพิ่มแพ็กเกจใหม่** (รหัส a-z0-9-_), **ลบ** แพ็กเกจที่ไม่มีผู้ใช้ (ลบ Free ไม่ได้) — API: `POST /plans`, `PATCH /plans/:id`, `DELETE /plans/:id`
- จัดการผู้ใช้ → เลือกแพ็กเกจ + วันหมดอายุ และ **สิทธิ์เฉพาะคนนี้ (ทับแพ็กเกจ)**: โควตาอุปกรณ์/ไซต์/กล้อง, บันทึกคลิป, ช่องทางแจ้งเตือน, วันเก็บข้อมูลเซนเซอร์ (หรือไม่จำกัด) — เว้นว่าง = ตามแพ็กเกจ (`PATCH /users/:id {plan_overrides}`)

### สมาชิกที่ไม่มีอุปกรณ์ของตัวเอง
บัญชีที่ไม่มีอุปกรณ์เป็นของตัวเอง (ใช้เฉพาะอุปกรณ์ที่เจ้าของแชร์ให้) **ไม่ต้องมีแพ็กเกจ/ไม่มีวันหมดอายุ**: ไม่แสดงสถานะหมดอายุ, ใช้ช่องทางแจ้งเตือนได้ทุกช่องทางเพื่อรับแจ้งเตือนของอุปกรณ์ที่ถูกแชร์ และเมื่อเริ่มเพิ่มอุปกรณ์ของตัวเอง สิทธิ์ตามแพ็กเกจจึงเริ่มมีผล
นอกจากนี้ ในโหมด `REGISTRATION_MODE=invite` อีเมลที่มีคนแชร์อุปกรณ์ให้ไว้แล้ว **สมัครได้โดยไม่ต้องมีรหัสเชิญ** (ต้องยืนยันอีเมลถ้าเปิดไว้ แล้วแชร์จะมีผล) — โหมด `closed` ยังปิดรับทั้งหมด

### แนะนำสมาชิก (Referral) + โปรโมชันเพิ่มวัน
- สมาชิกทุกคนมีรหัสแนะนำ 8 ตัว (แท็บบัญชีในแอป มีปุ่มแชร์) ผู้สมัครใหม่ใส่รหัสตอนสมัคร (`referral_code`) — ในโหมดเชิญ รหัสแนะนำใช้แทนใบเชิญได้ รหัสผิด = สมัครไม่ผ่านพร้อมแจ้งให้แก้
- รางวัล (ตั้งที่ Web Admin → โปรโมชันแนะนำสมาชิก): ผู้แนะนำได้ N วัน/คน, ผู้สมัครใหม่ได้ M วัน, แพ็กเกจรางวัล (ค่าเริ่มต้น Pro 30/14 วัน), จำกัดจำนวนคนที่ได้รับรางวัลต่อผู้แนะนำ (ค่าเริ่มต้น 12, 0 = ไม่จำกัด), เปิด/ปิดโปรโมชัน
- วิธีให้วัน: ผู้ใช้ Free หรือแพ็กเกจหมดอายุ -> เปลี่ยนเป็นแพ็กเกจรางวัลนับจากวันนี้; ผู้ที่มีวันหมดอายุอยู่ -> ต่ออายุเพิ่ม; แพ็กเกจถาวรไม่มีวันหมดอายุและ admin -> ไม่เพิ่ม
- ถ้าเปิดยืนยันอีเมล รางวัลจะจ่ายหลังผู้สมัครยืนยันอีเมลเท่านั้น (กันสมัครอีเมลปลอมเพื่อสะสมวัน); ตารางรายการแนะนำดูได้ที่หน้าเดียวกัน
- ข้อควรระวัง: ยังกันการสมัครหลายบัญชีของคนเดียวกันได้แค่ด้วยเพดานรางวัลต่อคนและการยืนยันอีเมล
